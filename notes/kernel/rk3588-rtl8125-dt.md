# RTL8125 PCIe Ethernet in DT on Rockchip boards (+ `realtek,rtl8125` binding)

Status IDs: **K4** (board DTs) and **K4b** (binding, split out). K5 (`-v6-next`) was superseded by K4 and deleted.
Last updated 2026-11-08. v1–v5 were sent; v6 (DTs) and binding v1 (net-next) are prepared but **not sent**.

## What it does

Several rk35xx boards have on-board RTL8125 2.5GbE NICs behind PCIe root ports, but the DT does
not describe the PCI function nodes. Describing them (root port `pcie@0,0` → `ethernet@0,0`,
`compatible = "pci10ec,8125"`, 5-cell `reg`) gives:
- stable `ethernetN` aliases (same convention as the GMACs);
- U-Boot `fdt_fixup_ethernet()` can inject `local-mac-address` from `ethaddr`/`ethNaddr`, so the MAC
  is stable and U-Boot and the kernel agree on it.

The kernel binds the DT node by `reg` (`pci_set_of_node()` → `of_pci_find_child_device()`);
the compatible string is not used for matching.

Boards: NanoPC-T6 (+LTS), ROCK 5B/5B+/5T (shared dtsi), ROCK 5T (2nd NIC), CM3588 (the NIC is on the SoM, so it goes in `rk3588-friendlyelec-cm3588.dtsi`),
NanoPi R5S (rk3568), NanoPi R6C, ROCK 5 ITX.
