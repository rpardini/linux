# ThinkPad X13s (sc8280xp) on Armbian 7.3.1-edge: session notes, 2026-11-04/05

Machine: Lenovo ThinkPad X13s 21BX001LGE, BIOS N3HET91W (1.63), 192.168.66.19.
Kernel: mainline v7.3.1 + Armbian `sc8280xp-edge` patches, branch `armbian-armsurvivors-sc8280xp-7.3-20261104-x13s`.
Distro: Debian trixie (Armbian). Tested from NVMe and from a USB-C disk; images were CLI (cloud) and KDE.

These are carried in Armbian as `patch/kernel/archive/sc8280xp-edge/0301..0303-*.patch`.

### Iris (video decoder)

- Symptom: `qcom-iris: core init failed`.
- Cause: the branch patch `3a273a0f7d640` ("add sc8280xp Gen2 platform data", for the Radxa Q8B) made sc8280xp
  **Gen2-only**. The X13s TrustZone accepts only Lenovo-signed firmware (`qcvss8280.mbn`), which is **Gen1**
  (`video-firmware.1.1`). Generic `qcom/vpu/vpu20_p4_gen2_s6.mbn` fails PAS auth with -22 (TZ signature check).
- Fix: add a Gen1 descriptor to `sc8280xp_data`; the existing autodetect picks Gen1/Gen2 from the firmware version
  string.
- A "memory rework" (Q8B-style carveout move plus `iris_iova`) was tried, reverted, and dropped: not needed.

### Iris firmware hang ("wedge")

- ffmpeg 7.1's `hevc_v4l2m2m` hits an assertion at end-of-stream (`Assertion pkt failed at ffmpeg_dec.c:758`) and exits
  **without** `VIDIOC_DECODER_CMD(STOP)` (proven with kprobes). The teardown flush then times out, the firmware is hung,
  every later session open fails, and runtime PM loops on "skip power collapse" until reboot.
- A mid-stream SIGKILL does *not* wedge it (H.264 or HEVC); only the "all input consumed, no drain" state does.
- Fix (`2f1f6ab852f69`): `iris_core_recover()`. On the first session-response timeout of a healthy instance, mark core
  and instances ERROR and schedule `sys_error_handler` (firmware reload), as for HFI_EVENT_SYS_ERROR. Stale instances
  don't retrigger it.
- Verified: after the ffmpeg wedge the log shows "firmware not responding, reloading", the next decodes work at once,
  and HEVC stays bit-exact.
- GStreamer (`v4l2h264dec`/`v4l2h265dec`/`v4l2vp9dec`) drains correctly. Full 1080p H.264/HEVC and 720p VP9 decode
  bit-exact vs software.
- TODO (optional): report the ffmpeg bug upstream.

### Audio (not fixed: left to upstream)

- Both wcd938x buses (RX `3210000`, TX `3330000`) clash from the first frame (`comp_status=0x2A01`, MASTER_CLASH_DET),
  and no slave ever attaches. WSA speakers enumerate fine.
- wcd938x TX init times out, so `snd-sc8280xp: failed to instantiate card -110`.
- Ruled out on the live system: reset gpio106 (deasserted), supplies, LPI pin mux/pull/drive/slew, macro clock gates,
  runtime PM (pinned everything on: no change).
- 6.16 (jhovold `wip/sc8280xp-6.16`) worked, so this is a **6.16 → 7.3 regression**. Candidates: SoundWire core/qcom 7.x
  changes, LPASS macro + LPI pinctrl PM-clk conversions, wcd938x/wcd-common refactor.
- Also seen: rmmod/reload of `soundwire_qcom` fails (`request_irq(0)`) plus a regulator WARN on unload; `qcom-apm`
  GET_SPF_STATE timeout at boot (benign).

### Other kernel notes

- `tpm_qcom_qsee: unsupported TPM type (dTPM)` (branch's own driver) correctly declines; could be demoted to `dev_info`.
- lpass rx/wsa macro "Unsorted reg_defaults" plus wsa "zero-initialized flat cache" warnings (cosmetic).
- upower: `qcom-battmgr-usb without usb_type property` (cosmetic).
- `UCSI_NO_PARTNER_PDOS` quirk means no PD contract details (voltage 0 in sysfs). Intended.

### Details and gotchas

- **pd-mapper**: both kernels have `QCOM_PD_MAPPER` built in. The userspace one raced ("no pd maps available") or
  registered a duplicate locator. Existing installs may still have the package and the override file.
- **alsa-ucm-conf**: 1.2.14 breaks the mics (jhovold wiki). The backports 1.2.16.1 needs `libasound2t64 >= 1.2.15`, so
  both `src:alsa-ucm-conf` and `src:alsa-lib` are pinned. The hook installs only `alsa-ucm-conf` (pulls
  libasound2t64/-data along).
- **libcamera/pipewire pin** (pin only, by request): CLI images aren't affected. **On desktop images use
  `apt full-upgrade`**: plain `apt upgrade` keeps 10 PipeWire packages back (new dep `libcamera0.7`) and leaves PipeWire
  half 1.4.2 / half 1.6.9.
- **Bluetooth**: without a public address the controller is *unconfigured* and absent from `btmgmt info`. Wait on
  `btmgmt --index 0 config` instead. `btmgmt` quits on stdin EOF (units have `/dev/null`) before replying, so it must be
  fed `yes 2>/dev/null |`. Address = `02:` + sha256 ("bt:<soc serial>"); for this unit `02:7d:64:ff:de:ac`.
- **Wi-Fi**: the hardware MAC is `00:03:7f:12:xx:xx`, random every boot (seen: 9f:e2, 2d:ed, c0:ef, a5:6f). A udev rule
  on `KERNELS=="0006:01:00.0", DRIVERS=="ath11k_pci"` runs `/usr/lib/armbian/thinkpad-x13s-wifi-mac $name`. MAC =
  `02:` + sha256 ("wlan:<soc serial>"); for this unit `02:a9:93:07:2d:a5`. The old NVMe netplan `wifi.yaml` pinned
  `macaddress:` (that *sets* the MAC).
- **SoC serial**: `/sys/devices/soc0/serial_number` (fuses), `3301291714` here. Survives reinstalls; machine-id is the
  fallback.
- **initrd**: `qcom_q6v5_pas` boots ADSP/CDSP/SLPI before switch-root with a single firmware request each, so all 3 DSP
  blobs must be in the initrd. The ADSP hosts pmic_glink (USB-C orientation/SuperSpeed, charging). msm is builtin, so
  the zap shader `qcdxkmsuc8280.mbn` must be there too. USB-C ports are `dr_mode = "host"`. USB-C boot verified at 10
  Gbps.
- **initramfs `modules` file**: trailing text after a module name is passed as module params, so comments go on their
  own line.
- **Firmware trim**: removes
  intel/nvidia/amdgpu/netronome/mellanox/mrvl/i915/xe/radeon/qed/dpaa2/liquidio/cxgb4/ath12k/ath10k/rkwifi/ti/ti-connectivity/cirrus,
  `qcom/*` except sc8280xp, and `ath11k/*` except WCN6855. Keeps USB-dongle firmware. Rootfs 3491 → 1689 MiB, image
  5544 → 3200 MB, firmware 2.2 GB → 365 MB. An apt upgrade of armbian-firmware-full restores everything.

### Not changed (decided against or out of scope)

- Wi-Fi power-save udev rule (`packages/bsp/common/.../10-wifi-disable-powermanagement.rules`) uses `%k` and runs on the
  pre-rename `wlan0`, so it fails silently on every board. Fix: `$name`. Not done.
- `splash plymouth.ignore-serial-consoles` cmdline from `extensions/grub.sh` is intentional.
- Desktop image: KDE PowerDevil warns locale is `"C"`, not UTF-8.
- `Tainted: unmerged-bin`: stock Debian trixie (`/usr/sbin` not merged into `/usr/bin`); ignore. No forky plan. (Saved

## 5. Suspend / resume investigation (open)

Only `s2idle` is available (`mem_sleep: [s2idle]`). Root on NVMe for the tests.

| Test                                                                       | Result                                                                                            |
|----------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| `pm_test=freezer`                                                          | ✅                                                                                                |
| `pm_test=devices` (all drivers suspend/resume, no idle)                    | ✅                                                                                                |
| real s2idle, power-button wake                                             | ❌ reset ~30 s after the button press                                                             |
| real s2idle, RTC wake (`rtcwake -m mem -s 20`)                             | ❌ reset around wake time                                                                         |
| real s2idle, RTC wake, **`cpu-sleep-0-0` disabled on all CPUs (WFI only)** | ✅ resumed; no errors; DSPs/BT/Wi-Fi/Ethernet back. Slowest resume: ath11k 1.17 s, PCIe 0.2–0.3 s |

- The journal ends at `PM: suspend entry (s2idle)`. No pstore (no ramoops region on this platform). The Linux `qcom_wdt`
  is inactive, so this is a firmware-level reset.
- Deep idle works **at runtime**: `cluster-sleep-0` (PSCI `0x4100c344`) was used 325× and per-CPU power-collapse >600×
  per CPU. So the failure is s2idle-specific: with all devices suspended, the RPMh votes drop to their floor and the
  cluster power-down then attempts a deeper system-level state that resets.
- The lid "i" LED doesn't pulse under Linux s2idle (nothing drives it).
- **Next steps:**
    1. Repeat the plain s2idle RTC test with the USB hub unplugged (jhovold wiki lists USB suspend issues).
    2. Then with the audio modules unloaded.
    3. Then the PCIe devices (Wi-Fi/modem; NVMe root last).
    4. Workaround if needed: a systemd-sleep hook that disables `cpuidle/state1` for s2idle only (higher sleep drain).
- Possibly relevant 7.x commits to look at: `7602c0ec0bbfd` (psci: pm_set_*_via_firmware for SYSTEM_SUSPEND),
  `0606f2114e2dc` (cpuidle-psci probe deferral / faux device).
